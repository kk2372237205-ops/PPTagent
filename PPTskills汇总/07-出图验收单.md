## 六、产品决策（项目 owner 已确认，勿再反复）

### 6.1 「参考图配色」≠「参考图当素材」

这是两个必须分清的术语，混在一起会导致改错方向：

| 术语 | 含义 | 用途 |
| --- | --- | --- |
| **参考图配色** | 一个**配色模式**：从一张图提取**颜色关系**，让生图模型弄懂这个主题的配色 | ✅ 只提供**颜色**：背景 / 表面 / 主文字 / 次文字 / 强调色及使用比例 |
| **参考图当素材** | 把图里的**内容**（照片、图表、截图）拿进页面 | ❌ **不使用**。已实测过：会和 Image2 的单张成图打架，出现"图生成了但后加的图不知道往哪放"的割裂感 |

`palette-reference.md` 要求把参考图**原文件**交给 Image2（"不能只传文字色值"），指的是**让模型看图取色**——图模型看图取色比读十六进制色值准得多。**它不等于允许抄参考图的版式或内容。**
因此把参考图作为 `image` 输入时，提示词必须同时写明："只学颜色关系与气质，不得复制其版式、构图、文字、logo、人物、图像或主题内容。"

### 6.2 用户资料里的图片不作为页面素材（设计如此，不是缺陷）

`scripts/deck-generation-worker.mjs:40`：

```js
const advancedSourceVisualReuseEnabled = false;
```

这**不是待修的缺陷，而是确认过的设计**：页面必须是"一整张自洽的生成图"。从资料里抽真图再塞进页面会让成图与后贴图互相干扰。

### 6.3 那"真实性"怎么保证

```
不使用资料真图  →  模型只能生成画面
不得伪造证据    →  不许画假照片、假证书、假现场、真人
        ↓
结论：插图必须是「一眼看出是画」的插画（扁平矢量 / 剖面 / 概念图）
      而且要够大（≥25%，一般 35–55%）、够具体（≥3 个具体名词）、承担信息
```

**这正是本次 skills 改动的方向。** 真实照片如果需要，是在"图片转 PPT"之后由项目 owner 自行处理，不在这张生成图里。

> ⚠️ 给下一个接手的人：不要因为看到"用户要求用真实图片"就去打开 `advancedSourceVisualReuseEnabled`。
> 那条路已经试过并且被否决了。用户资料图片只用于 OCR / 语义理解与配色提取。
