# slide_image_specs.json

## 职责

定义每一页具体怎么生成。图片模型只看最终 prompt，但 prompt 必须来自这里。

## JSON 结构

```json
{
  "slides": [
    {
      "slide_index": 1,
      "title": "",
      "content_summary": "",
      "composition": "",
      "main_visual": "",
      "illustration_share": 45,
      "director_contract": {
        "visual_weight": "balanced",
        "visual_units": [],
        "integration_rule": ""
      },
      "inherited_elements": ["", ""],
      "changed_elements": ["", ""],
      "text_density": "low",
      "white_space": "",
      "must_include": ["", ""],
      "must_avoid": ["", ""]
    }
  ]
}
```

## 规则

### 页面结构

- 每页必须是完整 16:9 PPT 页面。
- 第 1 页必须是 `cover`，最后 1 页必须是 `ending`。
- 中间页必须是内容角色，只能使用 `problem`、`insight`、`solution`、`architecture`、`feature`、`scenario`、`data`、`roadmap`。
- 中间页不允许使用 `cover` 或 `ending`。
- `title` 必须是纯标题，不要带页码、序号、`01`、`第 1 页`、`1.` 这类数字前缀。
- 不要把页码做成左上角或标题旁的大号数字装饰；如需页码，只能作为统一页脚或角落里的小辅助信息。

### `illustration_share`（插图面积份额）—— 必填数字

**这是本文件最重要的字段。** 只描述"画什么"而不写"占多大"，图片模型会把插图压成装饰角标，或者干脆不画。

> ⚠️ **必须同时用文字复述一遍。** 后台的 `normalizePlan`（`deck-generation-worker.mjs:1279-1295`）是严格白名单，`illustration_share` 这个新键**不会**被传下去。真正能到达图片模型的只有 `composition`、`main_visual`、`white_space`、`must_include`、`must_avoid` 这几个字段。
>
> 所以每一页都要做到**两件事**：① 在 `illustration_share` 里写数字；② 在 `composition` 里把这句写进去：
>
> ```
> 主视觉占画面 <N>%，是页面上最大的单一元素，高度跨度不低于画布高度的 75%，并出血到 <哪几条边>。
> ```
>
> 只做①不做②，数字会被丢掉，等于没写。

- 取值范围 25–100，单位是**占整张画布面积的百分比**。
- **正文页不得低于 25%。** 低于 25% 的画面在成品上等同于"没有插图"。
- 整页直接铺满的插图填 100。
- 图表页填图表本身的面积（图表就是那一页的插图）。
- 只有 `cover` 与 `ending` 允许填写 `100`；正文页填写 `100` 需在 `composition` 里说明文字如何浮在图上。

**面积下限对照：**

| 页面角色 | `illustration_share` 下限 | 期望区间 |
| --- | --- | --- |
| `cover` | 55 | 55–100 |
| `ending` | 35 | 35–60 |
| 正文页（一般） | **25** | 35–55 |
| 正文页（机制 / 场景 / 对比） | **40** | 45–70 |
| 图表页（`data`） | 45（图表面积） | 50–70 |

**整套面积节奏（必须同时满足）：**

- 相邻两页的 `illustration_share` 差值不超过 ±25，避免忽大忽小。
- 每 3 页至少有 1 页 `illustration_share ≥ 60`。
- 连续 2 页以上 `≥ 60` 之后，下一正文页必须回落到 45 以下，避免整本压抑。
- **任何正文页都不得为 0。** 唯一允许"没有插图"的是图表页和纯数据表页，而它们的图表本身就是插图。

### 画面单元

- 高级版每个正文页规划 **1 个主导画面单元**；只有当信息确实是并列的多阶段、多对比时，才增加到 2–3 个。
- **不要为了凑数量拆成多个小单元。** 3 个各占 8% 的小图，效果远差于 1 个占 45% 的主画面。
- 高密度页最多 4 个画面单元，且其中必须有一个是主导单元（≥ 该页插图画面的 50%）。
- **不允许出现"纯文字页"**。如果某页确实没有可画的实物，就画它的**结构**：把并列项做成带方向的过程链、把层级做成剖面、把对比做成左右分栏。结构图也是插图。
- 每个画面单元必须服务某条正文、阶段、对比、机制、背景或结果，并与对应文字共同形成阅读路径。
- 描述画面单元时**必须使用具体名词**。`growth`、`innovation`、`future`、`科技感` 这类抽象词不是有效的画面主体，模型只会把它们画成渐变球或通用图标。
- 图片位置由语义决定，不能把全部页面固定成左文右图、上文下图或统一底部图片区。
- 所有画面、文字和图表仍由 Image2 在一次请求中生成成一张完整页面图，不存在后插图步骤。

### 其他

- `main_visual` 只描述与项目有关的整体视觉方向，不要乱加无关机器人、人物或城市；它可以统筹多个互相关联的画面单元。
- `inherited_elements` 必须引用 visual_identity 和 storyboard 中的统一元素。
- `changed_elements` 负责让页面有变化。
- `text_density` 使用 low / medium / high：封面和结尾固定 low，普通正文 medium，资料型综述和数据页可用 high，但必须分区清楚且可读。
- **`illustration_share ≥ 55` 的页面必须使用 `low` 或 `medium` 密度**，正文控制在 45 个词以内。插图与文字在同一张 16:9 画布里抢像素，插图主导的页面不允许同时堆高密度文字。
- 所有重要文字、图表、底部横幅、页脚和装饰必须留在安全区内，距离四边至少 6%，不要贴边，不要被裁切。
