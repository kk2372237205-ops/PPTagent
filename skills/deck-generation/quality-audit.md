# 后台交付安全检查

## 执行时机

- 高级版不做逐页 GPT 看图质检；Image2 返回页面后立即保存并进入预览。
- 全部页面完成后，只调用一次 GPT-5.6 检查整套缩略图。
- 这一步是安静的安全兜底，不是新的用户确认环节，也不是审美返工流程。

## 只检查致命问题

以下问题标记为 `critical`：

- 空白、损坏或没有形成完整 16:9 页面。
- 大面积乱码、正文整体不可读或核心内容被严重裁切。
- 明显伪造的可识别学校/机构招牌、logo、证书、合同、报告、产品标签、客户证明或官方截图。
- 画面与本页标题直接冲突，已经达到无法交付的程度。

配色变化、一般审美偏差、页面之间合理的构图变化都不能触发 `critical` 警告。

## 插图面积自检（零成本，只提示不返工）

同一次调用里顺带完成**插图面积估计**，输出为**提示**（notice），不是警告，也不是返工触发条件：

对每一页给出：

- `illustration_share_estimate`：目测插图（含图表、机制图、场景图、概念插画）占页面的百分比，取 5 的倍数。
- `dominant_visual`：`yes` / `no` —— 页面上是否存在一个明显大于其他元素的画面主体。
- `fragment_count`：画面被拆成多少个互不相连的小元素（小图标、小缩略图、小圆点各算一个）。

**判定规则（只提示，不自动重绘、不增加用户成本）：**

| 情况 | 提示文案 |
| --- | --- |
| 正文页 `illustration_share_estimate < 25` | 本页插图偏小，接近纯文字排版，建议重做本页 |
| 正文页 `dominant_visual = no` 且 `fragment_count ≥ 4` | 本页画面被拆成多个小元素，建议合并成一个主要画面后重做 |
| 正文页 `illustration_share_estimate = 0` 且不是图表页/数据表页 | 本页没有任何插图，建议重做本页 |
| 相邻两页面积差 > 25 | 整套画面节奏忽大忽小，建议统一其中一页 |

**这几条只出现在任务顶部的提示区，由员工决定是否点击"重新生成本页"。** 系统不自动调用 Image2，不自动重绘，不产生额外费用。

> 为什么必须加这一条：插图过小、插图很假、整页没有插图，过去全部落在"一般审美偏差"里被明确排除在检查范围之外，因此**永远不会被发现**。加上这一项之后，问题第一次变得可见——而且不花一分钱。

## 处理规则

- 检查只标记 `critical` 页面，不自动调用 Image2，不自动重绘，不增加用户成本。
- **插图面积提示同样不触发自动重绘**，只作为员工返工的参考依据。
- GPT-5.6 检查暂时不可用时，保留已生成页面并正常进入预览，不把服务异常转嫁成用户返工步骤。
- 只有发现致命问题时才在任务顶部提示对应页码；具体是否重生由用户决定。
- 用户仍可主动点击"重新生成本页"或"更贴近上一页"，每次只增加一次明确的 Image2 调用。
- 每页只保存 Image2 生成接口、参考图数量、参考传递方式和调用记录，不保存逐页质检报告。
